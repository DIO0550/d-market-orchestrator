# テストシナリオ・チェックリスト

テストケースの**不足**を検出するための照合用リスト。
d-market-spec の spec-plugin（`spec-driven-dev-exp`）から写したもの。特定の言語・プラットフォームに依存する記述を落として抽象度を1段上げてある。
planner がテストケースを洗い出すときと、`test-coverage-checker` が不足を照合するときに使う。

## 使い方

1. 対象の機能タイプを1つ選ぶ（複合的な場合は該当する複数タイプのリストを合成する）
2. そのタイプのシナリオ行を、実際に書かれたテストケースと照合する
3. **対応するケースが無い行**を不足として報告する。「その機能では原理的に発生しない」なら不足ではない（例: 入力を取らない処理に境界値は無い）

各行末の `(該当時)` は、その性質を持つ機能にだけ適用する条件付き項目。

## 機能タイプ別シナリオ

### Pure Logic（入力→出力の純粋な変換・計算・判定）

- 正常系: 代表的な入力で期待結果を返す
- 正常系: 入力パターンのバリエーション（分岐を網羅する）
- 境界値: 最小値・最大値・ゼロ・空
- 異常系: 型が不正・値が欠落している入力
- エッジケース: 空コレクション・空文字列・特殊文字
- べき等性: 同じ入力で常に同じ出力 (該当時)

### Data Transformation（データ形式の変換・整形・集約）

- 正常系: 標準的な入力の変換
- 正常系: 複数の入力形式
- 境界値: 空データ・要素1件・大量データ
- 異常系: 不正な形式・必須フィールドの欠損
- べき等性: 同じ入力で同じ出力
- パフォーマンス: 大量データでの処理時間 (該当時)

### External Integration（外部サービス・API・DB・ファイルシステムとの通信）

- 正常系: 成功レスポンスの処理
- 異常系: 相手側が返すエラー応答の処理（クライアント起因・サーバー起因を分ける）
- 異常系: 通信不能・タイムアウト
- エッジケース: 空レスポンス・パースできない応答
- リトライ: 再試行ロジックの動作 (該当時)
- 認証: 資格情報の付与・更新 (該当時)
- **モック戦略**: 外部依存をどう差し替えるか明記されているか

### State Management（状態の保持・遷移・通知）

- 初期状態: デフォルト値
- 状態遷移: 各アクション/イベントによる遷移（**すべての遷移を1本ずつ**）
- 副作用: 状態変更に伴って起きるべき処理
- 競合: 同時更新・順序が入れ替わった場合の整合性
- 永続化: 保存と復元 (該当時)
- 通知: 変更の購読者への伝播 (該当時)

### Async Operations（非同期・並行処理）

- 正常完了: 成功パス
- 異常系: 失敗時のハンドリング
- タイムアウト: 制限時間超過
- キャンセル: 実行中の中断 (該当時)
- 競合: 複数処理の実行順序・レースコンディション
- リトライ: 再試行 (該当時)

### Security/Auth（認証・認可・入力の無害化）

- 正常系: 正当な資格情報でのアクセス成功
- 異常系: 無効・期限切れの資格情報
- 認可: 権限不足での拒否
- 認可: ロール・スコープ別の制御 (該当時)
- 無害化: 悪意ある入力の無害化（実行環境に応じた注入攻撃）
- セッション: 生成・維持・破棄 (該当時)

### Configuration（設定・オプションの解決）

- デフォルト値: 未指定時のフォールバック
- 値の切り替え: 設定変更の反映
- バリデーション: 不正な設定値の拒否
- 優先順位: 複数の設定ソースの優先順位
- 環境差異: 環境ごとの切り替え (該当時)

### UI Component（画面部品。UIを持つプロジェクトのみ）

- 表示: 各状態（初期・処理中・エラー・空・データあり）での表示
- 操作: ユーザー操作に対する反応
- 入力検証: 必須・形式・エラー表示 (該当時)
- アクセシビリティ: 支援技術・キーボードからの操作 (該当時)

### Resource Lifecycle（リソースの取得と解放。ハンドル・監視・購読・接続など）

- 取得: 対象が存在する場合・存在しない場合
- 反映: 操作後の状態確認
- 動的変化: 実行中に対象が増減した場合の追従 (該当時)
- クリーンアップ: 解放漏れがないこと（購読解除・接続クローズ）
