# レビュアー共通の指示

`spec-orchestrate` から起動されるレビュアー（`plan-reviewer` と、実装の検証の `*-reviewer`）が共通で従う。
**観点は各エージェントの定義が持ち、ここは観点に依らない指示だけを持つ。** どれを呼ぶか・起動の順序は `SKILL.md` が持つ。

## 受け取るもの

呼び出し側のプロンプトに次が入っている。入っていない項目があれば、それ自体を指摘として返す。

- **run フォルダ** `{dir}` — `.plugin-workspace/.orchestrate/{nnn}-{feature}/`
- **差分の基準**（実装の検証のときだけ）— `{dir}/BASE` のコミット。差分は次で出す（未追跡ファイルを含める）

```bash
base=$(cat {dir}/BASE)
git diff "$base"; git ls-files --others --exclude-standard
```

## 先に読むもの

1. `{dir}/requirements.md` — **ゴールと UC。ユーザーが確定した唯一の文書で、判断の基準**
2. `{dir}/implementation-plan.md` — 計画・採用した案・**却下した案とその理由**。却下済みの案を、新しい根拠なしに再提案しない
3. `{dir}/decisions.md`（あれば）— 承認後に AI が決めた判断。同じ論点を蒸し返すなら、その判断の理由のどこが崩れているかを示す
4. プロジェクトの規約 — `CLAUDE.md` / `AGENTS.md` / `CONTRIBUTING.md` と、そこから参照される規約ファイル（`rules/` `docs/` など。場所は `{dir}/exploration.md` の「踏襲すべき規約」）。**判断基準は規約と要件で、自分の好みではない**

## 指摘の書式

1 件ごとに次の項目を持たせる。

| 項目 | 書くこと |
|---|---|
| 重大度 | 重大 / 高 / 中 / 低（下の目安） |
| 信頼度 | 高 = 実測・再現した / 中 = コードで経路を辿れた / 低 = 推測（未検証と明記する） |
| 証拠 | `ファイル:行` と、そこに書かれているもの |
| 起きる場面 | どの入力・操作・状態で問題になるか |
| 結果 | 起きたら何が壊れるか・誰が困るか |
| 根拠 | 要件（UC-n）・計画・規約のどこに照らしたか |
| 直す方向 | 代わりにどうするか。パッチは書かない |
| 根本原因か症状か | 症状なら、どの根本原因から出ているか |

| 重大度 | 目安 |
|---|---|
| 重大 | データが壊れる・任意のファイルや権限に届く、のように取り返しがつかない |
| 高 | UC の成功条件を満たさない・利用者に見える誤動作・検査や CI が落ちる |
| 中 | 規約から外れ、次の変更で壊れやすくなる |
| 低 | 読み手が迷う程度 |

- **自分の担当の中で同じ根本原因から出ている指摘は 1 件に束ね**、症状はその中に並べる
- **観点ごとに見出しを立て、該当が無い観点も「無し」と、何を見てそう判断したかを 1 行で書く**（観点を省略しない。「問題ありません」だけの返答は検証になっていない）
- 最後に、重大度ごとの件数を 1 行で書く

## 指摘しないもの

- **数合わせの指摘。** 重要な問題が見つからなければ、そう書いて終える
- **証拠の無い理論上の可能性を、既存の欠陥として書かない。** 挙げるなら信頼度を「低」にする
- **好み。** 要件・規約・実害のどれにも結び付かないものは挙げない
- **差分と関係の無い既存の問題。** 差分がそれを悪化させる・前提にしているときだけ挙げる
- **担当外の観点。** 見つけたら、担当のエージェント名を添えて 1 行に留める

指摘する前に、**差分の箇所だけでなく呼び出し元・データの流れ・影響範囲まで辿る**。差分のその行だけを見た指摘は、呼び出し側で既に守られていることがある。見るほど新しい指摘が出なくなったら、そこで打ち切ってよい。

## ファイルを変更しない

**指摘だけを返す。実装の修正も、run フォルダの md の編集もしない。** 作業ツリーを書き換えてよいのはミューテーションを当てる `test-reviewer` だけで、その後始末は `test-reviewer` の定義が持つ。

- Bash を持つエージェントは、呼ばれた直後に `git status --porcelain` と `git diff | sha1sum` を控え、返す前に両方が同じであることを確かめる
- 挙動を再現して確かめるときは `mktemp -d` の一時ディレクトリで行う。作業ツリーの中で書き換えると、並列で動いている他のエージェントがそれを実装として読む
- `git add` / `commit` / `stash` / `checkout` / `reset` をしない
