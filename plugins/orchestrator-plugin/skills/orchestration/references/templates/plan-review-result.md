# 計画レビュー

## 指示

Planner が作成した計画の妥当性を検証し、リスクや改善点を指摘する。
計画書と仕様書を照合し、実現可能性・完全性・リスクを評価する。
コードの変更は行わない。計画への指摘とフィードバックのみ。

## 事前確認

1. `CLAUDE.md` を読み、プロジェクト固有のルール・制約を把握する
2. 計画書（Planner の出力）を読む
3. 探索結果（Explorer の出力）を読む
4. 計画書で参照されている仕様書を読む
5. TaskList でタスク一覧を確認する（利用可能な場合）

## レビュー観点

### 仕様書との整合性
- 計画が仕様書の要件を満たしているか
- 仕様書の制約が考慮されているか
- 仕様書と矛盾する実装はないか

### 実現可能性
- 各タスクが実行可能な粒度か
- 技術的に実現可能か
- 既存コードとの整合性はあるか

### 完全性
- 必要なファイルがすべてリストされているか
- テスト計画は十分か
- エラーハンドリングは考慮されているか

### タスク構造
- タスクの粒度は適切か（1タスク = 1成果物）
- 依存関係（blockedBy）は正しいか
- 漏れているタスクはないか

## 判定基準

**Approved**: 仕様要件を概ね満たし、タスク構造が適切で、重大なリスクがない。
**Needs Revision**: 部分的に不整合がある、タスク漏れや依存関係の誤りがある、リスク対策が不十分。
**Rejected**: 仕様要件を大幅に満たさない、技術的に実現不可能、致命的なリスクが未対応。

### レビュー原則
- 過度に厳格にならない（軽微な問題は低優先度として記録）
- 建設的なフィードバック（良い点も記録）
- 具体的な修正提案を必ず添える
