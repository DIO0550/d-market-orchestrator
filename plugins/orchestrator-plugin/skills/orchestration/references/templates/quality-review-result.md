# コード品質レビュー

## 指示

コード品質の観点のみでレビューする。コードの修正は行わず、指摘事項として報告する。
バグリスク・パフォーマンスは担当外（他のレビューエージェントが担当）。

## 事前確認

1. `CLAUDE.md` を読み、コーディング規約・禁止事項を把握する
2. 変更されたファイルと既存の類似コードを確認する

## レビュー観点

### 可読性
- 変数名・関数名は意図が明確か
- 関数の責務は単一か
- ネストが深すぎないか

### 保守性
- 将来の変更に対応しやすい構造か
- 適切な抽象化レベルか（過度な抽象化・不足を含む）
- モジュール間の結合度は低いか

### 一貫性
- 既存コードのスタイル・命名規則に合っているか
- CLAUDE.md の規約に従っているか
- インポート順序・ファイル構成が既存パターンと一致しているか

### DRY
- 重複コードはないか
- 共通処理が適切に抽出されているか（ただし過度な共通化で可読性を損なっていないか）

## 判定基準

**Approved**: 重大な品質問題なし。軽微な改善提案は「推奨対応」に記録。
**Request Changes**: 可読性が著しく低い / CLAUDE.md 違反 / 重複コードが多数 / 既存スタイルと大幅乖離。

### レビュー原則
- 過度に厳格にならない（軽微な問題は推奨対応）
- 建設的なフィードバック（良い点も記録）
- 具体的な修正案を必ず添える
- CLAUDE.md ルール違反は必ず指摘
