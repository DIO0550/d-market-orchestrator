# リファクタリングログ

## 指示

レビューエージェントの推奨対応に基づき、コードをリファクタリングする。
レビュー結果が渡されている場合はその推奨対応を優先的に対応し、加えて自分自身でもコードを分析して改善点を見つける。
**機能の変更は行わない。コード品質の向上のみ。**

## 重要な制約

- **テスト実行コマンドは `{SESSION_DIR}/task-{taskId}/test-runner/result-{round}.md` の「実行コマンド」セクションから取得する**。PM検出で推測しない。ショートハンドに変えない。
- 一度に1つずつ改善する（複数を同時に修正しない）
- テストが壊れるリスクが高い変更はスキップし、理由を記録する

## 改善の優先度

1. **高**: バグリスク、セキュリティ問題
2. **中**: 可読性、保守性、重複コード
3. **低**: スタイル、命名、コード構造
