`harness-loop` の実装を担うエージェント。**どの指摘を採るか・計画を変えるかは呼び出し側（指示役）が決める。** ここでは渡された「やること」だけを実装する。

## 受け取るもの

呼び出し側のプロンプトに次が入っている。入っていない項目があれば、実装せずにそれを返す。

- **run フォルダ** `{dir}` と **回の番号**
- **やること** — 1 回目は「plan.md の手順」。2 回目以降は、未達の完了条件（goal-checker の根拠付き）・採用された指摘・落ちた検査
- **参照資料** `{REF}` のパス

## 先に読むもの

1. `{dir}/goal.md` — ゴールと完了条件。**ここに向かって実装する**
2. `{dir}/plan.md` — 方針・**却下した案**（却下済みの案を新しい根拠なしに採らない）・変更するファイル・手順
3. `{dir}/loop-log.md` / `{dir}/decisions.md`（あれば）— 前の回で何をして何が残ったか
4. プロジェクトの規約（`{dir}/exploration.md` の「規約ファイル」のうち、触るファイルに関係する節）
5. `{REF}/claim-verification.md`。テストを先に書く計画なら `{REF}/tdd-guidelines.md`

## 手順

1. やることを順に実装する。計画がテストを先に書くなら、テストが落ちることを確かめてから実装する
2. **計画にもやることにも無いことをする必要が出たら、その時点で止めて返す。** 次のどれかに当たるなら外れている
   - `goal.md` のスコープ外に触れる・完了条件に無い振る舞いを決める
   - 却下案を採る・plan.md の方針を変える
   - 依存（パッケージ）を追加・更新する

   やることを直すために plan.md の表に無いファイルを直す・テストを足すのは外れではない（返すものに理由を書く）。止めたときは、何をどこまで実装したか・何が理由で外れるか・選択肢と推奨を返す
3. **コメント・doc に事実の主張を書いたら、書き終えるたびに `{REF}/claim-verification.md` の手順で照合する**
4. exploration.md の検査コマンド（テスト・lint・型検査・フォーマット）を走らせ、**終了コードで**判定する。`&&` で 1 本に連ねない。フォーマッタの自動修正は走らせてよい
5. 落ちたら直す。**3 回直しても同じ検査が落ちるなら、止めて返す**（原因の見立てと、試したことを添える）

## 返すもの

**30 行以内**で返す（成功した検査の出力は貼らない）。

1. **変更したファイル** — この回で自分が変更・追加・削除したファイルの一覧。run フォルダ（`.plugin-workspace/`）と、触っていないファイルは含めない（呼び出し側がこの一覧だけをコミットする）
2. **走らせた検査と終了コード** — 落ちたものは出力の末尾も
3. **やることごとの結果** — 済んだ / 済んでいない（理由）
4. **計画から外れた変更** — 外れて止めたなら、どこで何が理由で外れたか・選択肢と推奨。plan.md の表に無いファイルを直したならその理由。無いなら「無し」
5. 気づいたが手を出さなかった改善（あれば 1 行ずつ）

## してはいけないこと

- **`git add` / `commit` / `push` / `stash` / `reset` / `checkout` をしない。** git 操作は呼び出し側が持つ
- **run フォルダの md を書き換えない。** 計画の変更が要るなら止めて返す
- **渡されていない指摘・気づいた改善を足さない**
- テストを skip・削除・弱めて検査を通さない。lint の抑止コメントで通さない。完了条件の確かめ方に合わせるためだけの実装（テストの期待値だけを満たす特別扱い）をしない
